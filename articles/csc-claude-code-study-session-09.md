## 今日のゴール

「もう一人の自分」に調査や作業を任せる仕組みであるサブエージェントの考え方を理解し、実際に使ってみる。

## 座学

### サブエージェントとは何か

サブエージェントとは、メインの会話のコンテキストウィンドウを圧迫せずに、重い調査や作業を任せるための仕組みです。まずは、なぜこの仕組みが必要なのかを説明します。

第2回で、Claude Codeにはコンテキストウィンドウ(会話の文脈を保持できる容量)という限りある資源があり、これを使い切ると挙動が不安定になることを説明しました。

https://zenn.dev/cscloud_blog/articles/csc-claude-code-study-session-02

調査や下調べのために大量のファイルを読ませたり、Web検索を何度も行わせたりすると、そのやり取り自体がコンテキストを圧迫してしまいます。

この問題を解決するのが「サブエージェント」です。サブエージェントとは、メインの会話とは別に、独立したコンテキストを持つ「もう一人の自分」を呼び出し、そこに調査や作業を任せる仕組みです。サブエージェントが調べた大量の情報はサブエージェント側のコンテキストで処理され、メインの会話には要点だけがまとめられて返ってきます。  
これにより、メインの会話のコンテキストを汚さずに重い調査を進められます。

### 組み込みのサブエージェント

Claude Codeにはあらかじめ用意されたサブエージェントがいくつかあります。代表的なものは次のとおりです。

| サブエージェント | 役割 |
|---|---|
| Explore | 読み取り専用でコードやファイルを高速に探索する。「このキーワードはどこで使われているか」といった調査向け |
| Plan | 実装や作業の計画を設計する。複数の選択肢を比較検討させたいときに使う |
| general-purpose | 特定の役割に限定されない汎用的な調査・作業タスクに使う |

これらは特別な設定をしなくても、Claude Code自身が「今回は調査を任せた方が良さそうだ」と判断した場合に自動的に呼び出したり、こちらから名前を指定して呼び出したりできます。

### カスタムサブエージェントを作る

組み込みのサブエージェントに加えて、`.claude/agents/` というディレクトリに専用の定義ファイルを置くことで、自分たちの業務に特化したサブエージェントを作れます。

たとえば「セキュリティコードレビュー専門」「依存ライブラリの脆弱性監査専門」といったように、役割を絞り込んだ専門agentを用意しておくと、その都度長い指示を書かなくても、名前を呼ぶだけで専門的な視点でのレビューを任せられるようになります。

筆者の環境では、OWASP Secure Agent Playbookというプラグイン(プラグインについては前回扱いました)を導入しており、その中には次のような、役割を1つに絞ったサブエージェントが含まれています。

- コードのセキュリティ上の弱点だけをレビューする専門agent
- APIの設計を「OWASP API Security Top 10」(APIによくあるセキュリティ上の弱点をまとめたガイドライン)の観点でレビューする専門agent
- 依存ライブラリの脆弱性(CVE)を監査する専門agent
- これら複数の専門agentをまとめて同時に動かし、結果を1つにまとめる「security-team-lead」のようなまとめ役agent

まとめ役agentに「このプロジェクトをまるごとセキュリティレビューして」と依頼すると、内部で複数の専門agentが同時に異なる観点からレビューを行い、最後にその結果がまとめて報告されます。1つのagentに何もかも任せるより、観点ごとに専門agentへ役割分担させた方が、見落としが少なく、レビューにかかる時間も短縮しやすい傾向があります。

### Agent Skillとの違い・使い分け

第6回で扱ったAgent Skills(`.claude/skills/`に置く手順書)と、サブエージェントは、どちらも「`.claude/`の中に定義ファイルを置いてClaude Codeの動きをカスタマイズする仕組み」であり、似ているように見えます。しかし、仕組みは大きく異なります。

https://zenn.dev/cscloud_blog/articles/csc-claude-code-study-session-06

| | Agent Skill | サブエージェント |
|---|---|---|
| これは何か | メインの会話に読み込まれる手順書 | 独立したコンテキストを持つ、もう一人のClaude |
| コンテキストへの影響 | 発動するとメインの会話のコンテキストに本文が読み込まれる | メインの会話とは別のコンテキストで実行され、要点だけが返ってくる |
| 主な目的 | 手順・知識の再利用(定型作業のテンプレ化) | 大量の調査や複数の作業を同時に任せる(コンテキストの節約) |
| 定義場所 | `.claude/skills/<name>/SKILL.md` | `.claude/agents/<name>.md` |

迷ったときは、こう考えるとよいでしょう。手順に沿って進めたい定型的な作業ならSkill、メインの会話から切り離して大量のファイル読み込みや複数観点のレビューを任せたい作業ならサブエージェントです。専門化したサブエージェントの中でさらにSkillを使わせる、という組み合わせも可能です。どちらか一方だけを選ぶ必要はありません。

### Agent Team(実験的機能)

さらに発展的な仕組みとして、複数のサブエージェントがチームを組んで継続的に協力しながら動く「Agent Team」という機能もあります。
ここまで説明したサブエージェントは1回限りの作業を任せる仕組みですが、Agent Teamはそれをチーム単位に広げたものだとイメージしてください。

これは執筆時点では実験的機能であり、今後仕様が変更される可能性がある点に注意してください。
設定ファイルに `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` という環境変数を追加することで有効にできます。  
実験的機能を業務で使う際は、まず個人の検証環境で試し、挙動が安定していることを確認してから展開するようにしてください。

なお、今回のミニハンズオンではAgent Teamは扱いません。まずはこのあとのミニハンズオンでサブエージェントに作業を任せることに慣れてから、興味があれば個人の検証環境で試してみてください。

### TAM業務での並列化ユースケース

サブエージェントによる並列化は、コーディング作業に限った話ではありません。TAM業務でも、たとえば次のような場面で活用できます。

- 1つの提案書や設計書に対して、複数の異なる観点(セキュリティ、コスト、運用性など)から同時にレビューを走らせる
- 複数の情報源(公式ドキュメント、社内資料、過去の類似案件)を並行して調査し、後でまとめて比較する
- 診断したいシステムについて、観点の異なる複数の専門agentに最初のチェックを分担させる

たとえば、顧客への提案書レビューを1人で最初から最後まで通しで見ると、セキュリティの見落としに気づいた頃にはコストの観点を読み流してしまう、といったことが起きがちです。「セキュリティ観点」「コスト観点」を別々のサブエージェントに分担させれば、それぞれが該当箇所だけに集中してレビューでき、後から2つの指摘を並べて確認する形になるため、観点の抜け漏れに気づきやすくなります。

## ミニハンズオン

### 手順1: 調査をサブエージェントに任せてみる

作業フォルダの中に、複数の資料ファイルを用意します。過去に作成した報告書や調査メモなど、手元にあるテキストファイルを3件ほどコピーしておくとよいでしょう。手元に適当なファイルがない場合は、Claude Code自身に「架空のセキュリティ診断調査メモを3つ作って」のように頼んでサンプルを用意してもらっても構いません。準備ができたら、次のように依頼します。

```
このフォルダにあるファイルを調査して、共通して出てくるキーワードを
探してほしい。調査はサブエージェントに任せて、結果だけ報告して。
```

Claude Codeが「サブエージェントに任せた方がよい」と判断すると、Exploreやgeneral-purposeといったサブエージェントが呼び出され、ファイルの読み込みや探索が行われます。手元の会話画面には、その過程の詳細ではなく、要点をまとめた報告だけが返ってくることを確認してください。

### 手順2: 観点を分けて並列レビューを試す

同じ資料に対して、次のように依頼してみます。

```
この文書を、セキュリティの観点とコストの観点それぞれから
レビューしてほしい。2つの観点は別々のサブエージェントに
分担させて、それぞれの指摘を並べて報告して。
```

1つのagentがすべての観点を順番にこなすのではなく、観点ごとに担当が分かれて並行して動くことで、待ち時間を短縮しながらいろいろな角度からの指摘を得られることを体感してください。

### 手順3: カスタムサブエージェントを自作してみる

座学で紹介した `.claude/agents/` を使って、ごく簡単な専門agentを1つ自作してみましょう。作業フォルダで次のように依頼します。

```
.claude/agents/ に、Markdownの誤字脱字だけをチェックする
専門agentを作ってほしい。名前は「proofreader」にして。
```

Claude Codeが `.claude/agents/proofreader.md` のような定義ファイルを作成したら、内容を確認してみてください。役割や振る舞いが数行のテキストで定義されているだけであることが分かるはずです。定義ができたら、実際に次のように名前を指定して呼び出し、専門agentが動く様子を確認しましょう。

```
proofreaderに、このファイルの誤字脱字をチェックしてもらって。
```

## まとめ+チーム資産化アクション(5分)

- サブエージェントは、メインの会話のコンテキストを守りながら重い調査や作業を任せるための仕組みである
- 組み込みのExplore・Plan・general-purposeに加え、`.claude/agents/` で業務特化の専門agentを自作できる
- 観点ごとに専門agentへ役割分担させることで、レビューの見落としを減らし、時間の短縮にもつながりやすい
- Agent Skillはメインの会話に読み込まれる手順書、サブエージェントは独立したコンテキストで動くもう一人のClaudeという違いがある
- Agent Teamは実験的機能であり、業務利用の前に個人環境での検証を挟むこと

**チームへの持ち帰りアクション**: 自分たちの業務でよく発生する「複数の観点からのチェック」を1つ洗い出し、それぞれの観点をサブエージェントに分担させる依頼文を作ってみてください。うまくいった依頼文は、第6回で扱ったスキル化の候補としてメモしておくと、チーム資産として蓄積できます。

## ベストプラクティスのひとこと

Anthropic公式のベストプラクティスでは、「調査はサブエージェントに任せて、メインの会話のコンテキストを守る」ことが推奨されています。あわせて、会話が長くなるとパフォーマンスが低下する兆候にも注意が必要です。

https://code.claude.com/docs/ja/best-practices

| 兆候 | 考えられる原因 | 対処法 |
|---|---|---|
| 同じ間違いを繰り返す | コンテキストが埋まり、以前の指示が埋もれている | `/compact` で会話を要約する |
| 以前の決定と明らかに矛盾する回答をする | CLAUDE.mdや過去の指示が読み込まれていない | `/memory` で内容を確認し、記述を簡潔にする |
| 修正を依頼しても同じ箇所に戻ってくる | 計画を立てずにいきなり実装や作業を進めている | `/plan` で改めて計画段階に戻る |

こうした兆候が見えたら、一度立ち止まって `/compact` や `/clear`、あるいは `/plan` への立ち戻りを試すようにしましょう。
